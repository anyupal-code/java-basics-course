# Урок 12. Итоговый проект: Консольное приложение «Библиотека»

## Цель урока
Объединить все полученные знания (ООП, коллекции, исключения, даты) в одном завершенном проекте, который можно добавить в портфолио.

---

## Теория

### 1. Архитектура приложения
Хорошее приложение разделяют на слои, чтобы код было легко читать и менять. В нашем проекте будет три пакета (папки):
* `model` — классы данных (сущности). Например, `Book` и `Reader`.
* `service` — бизнес-логика (что можно делать с данными: добавить книгу, выдать её читателю).
* `ui` — пользовательский интерфейс (консольное меню, ввод/вывод).

### 2. Что должно уметь приложение
Наша «Библиотека» будет работать через консольное меню:
1. **Добавить книгу** (название, автор, год).
2. **Показать все книги**.
3. **Выдать книгу читателю** (книга помечается как выданная, запоминается дата выдачи).
4. **Вернуть книгу** (книга снова становится доступной).
5. **Выход**.

### 3. Использование знаний
* **ООП:** Классы `Book` и `LibraryService` с инкапсуляцией.
* **Коллекции:** Для хранения книг используем `Map<Integer, Book>` (где ключ — ID книги) или `List<Book>`.
* **Исключения:** Если книгу не нашли или она уже выдана, выбрасываем кастомное исключение.
* **Даты:** При выдаче книги записываем `LocalDate.now()`.
