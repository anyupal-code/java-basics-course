# Урок 11. Git и структура проекта

## Цель урока
Обобщить навыки работы с Git, научиться оформлять проекты для портфолио и понять, из чего состоит профессиональная разработка.

---

## Теория

### 1. Git — это не только сохранение файлов
Вы уже знаете, как делать `git add`, `commit` и `push`. Но Git — это еще и инструмент командной работы. 
В реальных проектах разработчики работают в отдельных ветках (branches).

* `git branch` — посмотреть список веток.
* `git checkout -b feature-login` — создать новую ветку для новой функции и сразу переключиться на неё.
* `git merge feature-login` — влить изменения из ветки `feature-login` в текущую (обычно в `main`).

Для нашего учебного курса мы делали всё в одной ветке `main`, но в реальной работе вы будете создавать ветки под каждую задачу.

### 2. Как писать хорошие коммиты
Сообщение коммита должно отвечать на вопрос «Что было сделано?».
* **Плохо:** `Update`, `Fix`, `Some changes`.
* **Хорошо:** `Add validation for user age`, `Fix NullPointerException in login`, `Update README with setup instructions`.

В идеале коммит должен быть атомарным (решать одну задачу). Если вы сделали 5 разных изменений — лучше сделать 5 коммитов.

### 3. Файл .gitignore
Мы уже создали `.gitignore` в начале курса. В реальной разработке этот файл критически важен. В него добавляют:
* Скомпилированные файлы (`.class`, `out/`);
* Настройки среды (`.idea/`, `.vscode/`);
* Пароли и ключи (`.env`, `secrets.properties`).

**Запомните:** никогда не коммитьте пароли и токены. Если вы случайно закоммитили пароль, его нужно немедленно сменить (даже если удалите файл, он останется в истории Git).

### 4. Что такое README.md
`README.md` — это лицо вашего проекта на GitHub. 
Хороший README должен содержать:
* **Название проекта** и краткое описание.
* **Стек технологий** (например: Java 25, Maven, PostgreSQL).
* **Инструкцию по запуску** (какие команды ввести, чтобы проект заработал).
* **Примеры использования** (скриншоты или примеры кода).

### 5. Структура проекта
Хорошо организованный проект выглядит так:
    my-project/
    ├── .gitignore
    ├── README.md
    ├── pom.xml (или build.gradle) — файл сборки
    └── src/
        ├── main/java/...       — исходный код
        └── test/java/...       — тесты

### 6. Пример работы с ветками (шпаргалка)

Представьте, что вы хотите добавить новую функцию в проект. Вместо того чтобы сразу менять `main`, вы создаете отдельную ветку:

~~~bash
# Посмотреть текущие ветки
git branch

# Создать новую ветку и сразу переключиться на нее
git checkout -b feature-add-book

# ... вносим изменения в код ...

# Сохраняем изменения в этой ветке
git add .
git commit -m "Add feature: create book"

# Возвращаемся в главную ветку
git checkout main

# Вливаем изменения из feature-add-book в main
git merge feature-add-book
~~~

После слияния ветку `feature-add-book` можно удалить (`git branch -d feature-add-book`), так как её работа выполнена.

### 7. Что дальше?
После окончания этого курса ваша главная задача — сделать **свой собственный проект**. 
Это может быть:
* Телеграм-бот.
* Приложение для учета расходов.
* Игра «Крестики-нолики» на консоли.
* REST API на Spring Boot (следующий уровень после нашего курса).

Наличие завершенного проекта на GitHub с хорошим README — это лучший способ показать работодателю, что вы умеете писать код.
